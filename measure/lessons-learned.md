### Recurring Gotchas
<!-- Problems encountered repeatedly; save future tracks from the same pain -->
- (2026-03, consolidated) Section toggles travel as query strings: wire a new toggle through the frontend state, the URL params, and the compile route, and read it with `=== 'true'` or `!== 'false'`, never a truthy check.
- (2026-03, consolidated) Next.js previews: print a Paged.js iframe with `iframeRef.current.contentWindow.print()` (`window.print()` prints the outer UI), and show `blob:` URLs with a plain `<img>`, not `next/image`.
- (2026-10-01, origins_app_refresh_20261001) mmx `--subject-ref` pulls image-01 to a 3D look, even from flat 2D sheets. For the same character in flat 2D, give the flat style and a full hair-and-clothes `look` in the text, with no reference. Repeat the full look of a non-cast person in every prompt. When a story changes a cast look (new shoes, a hat on a hand), leave that character out of `characters` and write the lesson's look in the prompt. mmx sometimes adds letters or a signature: check the corners.
- (2026-10-02, origins_app_refresh_20261001) Background jobs: Claude Code stops a background job when system memory is low, and `gcloud storage cp` can exit non-zero after a good copy (check size and md5; error text shows the end of stderr). Give a long production write to the user's terminal. `pkill -f <pattern>` also matches the shell that runs it (exit 144); stop a job by its PID.

- (2026-09-30, text_profile_lint_20260930) Measure a text baseline and its target with the same tool and basis. The Origins 3.1 "80% Starters" baseline counted names against the text (names are ~13% of tokens), while the target rule excluded names, so the 85% target was weaker than the printed books. Also: `primary/origins-2-a0/` holds teacher `.md` files; a lesson loader must require `_workbook.json` or draft front matter, and word matching must use the resolved lemma only ("his" is not "hi").
- (2026-10-01, review_page_20261001) `__dirname` is wrong inside the Next.js bundle (the review API read `/mastery-advantage/...`). Code that runs in both a CLI and a route must find the repo from `process.cwd()` or `WORKBOOKS_ROOT` (`findRepoRoot` in `lib/lesson-package/files.ts`). A Vitest route test does not catch this; run the route once in `next dev`.
- (2026-03-22, consolidated) Playwright locators: strict mode matches more than you expect — a label and its section header, a `CardTitle` (rendered as a `div`, so no heading role), or a Paged.js section split across printed pages. Prefer `getByLabel` or explicit locators over `getByText`, and `.first()` where a match may legitimately repeat.
- (2026-03-22, consolidated) Playwright timeouts: Paged.js is slow — a 14+ lesson workbook takes 45–60s to render. Use `test.setTimeout(90000)` for compile tests, ≥60000ms locator timeouts for elements at the end of the document, and ≥15000ms on `expect(page).toHaveURL()` after flows that write to disk before redirecting.
- (2026-03-22, consolidated) Playwright interactions: a modal with `fixed inset-0` intercepts pointer events for anything underneath — dismiss it with its own close control. Use `page.frameLocator('iframe')` rather than `.contentFrame()`, which evaluates synchronously and may hold a detached node after a remount. Verify checkbox state with `not.toBeChecked()`, then wait for the iframe to become visible again.
- (2026-03-22, e2e_testing_and_visual_stabilization_phase_10_20260322) Lesson naming conventions: Files in workbook projects MUST end with `_workbook.json` or start with `content_` to be recognized by `listLessons`. The `POST` API should strictly enforce this naming to ensure newly created lessons appear in the dashboard.
- (2026-03-22, e2e_testing_and_visual_stabilization_phase_10_20260322) Next.js Version Crashing: Updating Next.js beyond `16.1.6` (e.g. `16.2.1`) may trigger `bmi2` CPU instruction panics in environments with older/virtualized CPUs. Version `16.1.7` was found to be a stable middle ground that fixes vulnerabilities without causing panics.
- (2026-03-10, certificate_of_completion_20260310) Vitest HTML checks: When testing HTML generated from templates that contains complex dynamically injected CSS blocks alongside the required class names, use structural or exact tag checks (`<div class="section-certificate">`) rather than just `toContain('section-certificate')` to avoid false positives matching against the CSS `<style>` block itself.
- (2026-03, consolidated) Paged.js small rules: use `break-before: right` (or `break-after: page` on the element before) to push a section to a new page; keep `@page` rules only in the document wrapper, not in single templates; draw tracing text in light gray (`#e0e0e0`) with a sans-serif fallback.
- (2026-03-11, refactor_cleanup_20260311) Thematic consistency: When generating printable HTML sections, always utilize the provided `ThemeColors` to ensure visual consistency across the workbook. Avoid unused parameters which trigger ESLint warnings.
- (2026-03-11, e2e_testing_and_visual_stabilization_20260311) Playwright testing: Ensure `e2e` directories or `.spec.ts` files are explicitly excluded in `vitest.config.ts` to prevent Vitest from attempting to run E2E suites which causes build failures.
- (2026-04-26, primary_compile_layout_papercuts) Primary Step 11 Guided Writing is height-sensitive in print. To keep the section title and writing box together, trim the primary template vertically first: reduce padding, planner line count, draft line count, and QR block size before reaching for harder page-break rules.
- (2026-04-26, primary_pipeline_bugs) Imported primary lessons may still use legacy `article_image_url` arrays. The renderer tolerates them, but schema-backed edit/save paths expect `article_image_url` to be a string and `article_images` to hold positioned images, so canonicalize imported lessons before relying on validation.
- (2026-04-26, primary_compile_layout_papercuts) For primary Step 3 article pages, avoid using `overflow:auto` as a clearfix around floated article imagery in printable containers. In Paged.js it can interact badly with fragmentation and clip images at page boundaries. Use a clearfix pseudo-element instead, and if the QR intro keeps orphaning the section title, start the article step on a fresh page in print.
- (2026-04-26, thai_vocab_backfill_origins_a0) Bilingual support in this workbook stack is split: `vocabulary[].thai_definition` already feeds glossary/flashcards/teacher guide, but student lesson pages need explicit template rendering and worksheet matching needs its own `vocab_match[].thai_definition` if you want Thai to survive schema-backed editing instead of being baked into English strings.
- (2026-08-03, teacher_guide_renumbering) Step numbers are the **student workbook's**, not the app's. The manual carried a 14-step teacher sequence against a 13-step printed workbook for months. The app build still labels those screens 9–14, so any doc that renumbers must keep an explicit numbering note and leave `app step N.png` filenames on the app's scheme while `WB N` files follow the workbook's — otherwise the next editor "fixes" the mismatch back.
- (2026-08-03, teacher_manual_generation_20260426) Paged.js 0.4.3 paginates through a requestAnimationFrame callback chain (next frame scheduled only from the previous task's completion), so one dropped rAF — background tab, CPU contention, or a visible-but-occluded tab whose compositor delivers no frames while `visibilityState` stays "visible" — silently freezes the render at a low page count with an idle main thread. The rAF shim must never rely on visibility alone: arm every tick with both a native rAF and a setTimeout(0) fallback (first to fire wins, cancel the other) so progress is independent of frame delivery, and flush the hidden queue on visibilitychange. Also avoid `overflow:hidden` on fixed-height full-page elements (nondeterministic freezes).
- (2026-05-06, font_package_20260506) Publisher font handoffs should package redistributable Google Fonts from official `google/fonts` with OFL files; do not bundle proprietary fallbacks like Comic Sans MS or Chalkboard SE unless licensed and available.
- (2026-10-01, origins_app_refresh_20261001) App fallbacks: read the app code before you say what it shows for an empty field. The legacy Primary summary uses `translatedSummary[locale] ?? summary`, and `??` keeps `""`, so an empty `cn`/`vi` shows an empty box, not English. A wrong claim here led to a wrong product decision; write English (or the old value) into the field instead of `""`.

### Patterns That Worked Well
<!-- Approaches worth repeating -->

- (2026-04-08, ai_content_orchestration_20260408) Gemini structured output: Using `responseMimeType: "application/json"` with `zodToJsonSchema` to embed the full Zod schema in the prompt ensures Gemini returns valid JSON that passes `Schema.safeParse()`. This pattern (from ai-augmentor.ts) is reusable for any structured output from Gemini.
- (2026-04-09, ai_content_orchestration_20260408) Radix Select in jsdom: Radix UI Select component uses `scrollIntoView` which is not available in jsdom. Tests that interact with Select dropdowns in jsdom will fail. Either mock the component or use `@testing-library/user-event` which handles these cases better.
- (2026-04-09, ai_content_orchestration_20260408) Modal form reset: When using Radix Dialog with controlled open state, the form reset logic in `onOpenChange` only triggers when closing. To reset form when opening, use the same handler for both open and close, or reset state before calling setOpen(true).

### Rules for every Phase 2 task

- Tests first. A Red task writes failing tests and commits them. Its Green task makes them pass and changes no test file. A review role reports and does not fix code.
- A task becomes `[x]` only with `commit <sha>` on the task line itself and its evidence class: owner-approved, person-checked, automated, or peer-report. A self-report closes no task.
- Mark a task `[~]` before you change a file outside `measure/`.
- A task that waits for Daniel stays `[ ]`. Use the word "deferred" only in the trailer `— deferred:<owner>`. In other text, write "later" or "waits for".
- Heavy jobs (vitest, tsc, Chrome, Ghostscript, PDF/X builds, contact sheets) run with ONE command: `HEAVY_MIN_AVAIL_MB=1500 HEAVY_PREFLIGHT_WAIT_S=5400 bash ~/Desktop/advantage-pr/scripts/jobs/heavy-run.sh -c '<command>'`. Never nest a heavy-run. Never use a plain `flock` on the lock inside a heavy job.
- Every dashboard vitest command has `--maxWorkers=1` (PM memory order, 2026-11-07).
- No pnpm in any form. No `npm install`. No `npm ci`. Run `git checkout -- pnpm-lock.yaml` after a gate if the lock file changed.
- Stage files path by path with `git commit -- <paths>`. Never stage `video/storytime-song/scripts/render.mjs`, `dashboard/raw.json`, or `measure/runs/**` of other tracks. No push, no amend, no reset, no revert, no stash.

### Gate commands (orchestrator environment)

```bash
RED_TEST_COMMAND='cd dashboard && CI=true npx vitest run __tests__/storytime-cover-*.test.ts --maxWorkers=1'    # must fail after each Red, before its Green, and only in the new Red file
GREEN_TEST_COMMAND='cd dashboard && CI=true npx vitest run __tests__/storytime-cover-*.test.ts --maxWorkers=1'  # must pass after Green
PROJECT_TESTS='cd dashboard && CI=true npx vitest run __tests__/storytime-*.test.ts __tests__/covers-*.test.ts __tests__/print-pdfx.test.ts --maxWorkers=1'
PROJECT_LINT='cd dashboard && npx eslint lib/storytime scripts/storytime __tests__/storytime-cover-*.test.ts'
PROJECT_CHECKS='cd dashboard && npx tsx scripts/storytime/check-weeks.ts --level 2 && npx tsc --noEmit'  # the form of the print track since its review round 8 (F52): check-weeks exits 1 on any FAIL row, so a FAIL or a crash fails the gate; the whole command runs inside one heavy-run wrapper; no nested heavy-run
UX_REQUIRED=never   # print files: the visual checks are the look task and Daniel's check
PRINT_GATE='cd dashboard && npx tsx scripts/print/make-pdfx.ts <print file> --check'   # exit 0 for each of the 4 print files
```

The whole command of each gate runs inside one heavy-run wrapper. `PROJECT_TESTS` is the list of the print track, so a change in a shared module shows up there. This track changes no week file, so `check-weeks.ts` must give the same rows before and after each Green. If `PROJECT_TESTS` fails only in a test of another track that this track did not touch, the orchestrator records the failed test names and asks that track's session; this track does not edit that test.

Baseline: this planning session ran no gate. The Red 1 task records the baseline of `PROJECT_TESTS` (files, tests, failed names) at `red_base=$(git rev-parse HEAD)`.

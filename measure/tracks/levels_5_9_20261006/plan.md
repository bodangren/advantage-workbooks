## Rules for the grouping tasks (1.G1 to 1.G5)

- The strategy role runs before Task 1.G1. It assigns the review gates and the acceptance.
- Heavy jobs (every vitest run and every tsc run) run with ONE command: `HEAVY_MIN_AVAIL_MB=1500 HEAVY_PREFLIGHT_WAIT_S=5400 bash ~/Desktop/advantage-pr/scripts/jobs/heavy-run.sh -c '<command>'` (PM rule, advantage-pr 0e091de, 2026-10-25). Exit 75 means: the pre-flight hold lasted longer than its wait. Never nest a heavy-run.
- No pnpm in any form. No `npm install`. No `npm ci`. Run `git checkout -- pnpm-lock.yaml` after a gate if the lock file changed.
- Commit with `git commit -- <paths>` only. No amend, reset, revert, stash, or push. Never stage `video/**`, `dashboard/raw.json`, or the `measure/runs/` files of other tracks.
- Before a task changes a file outside `measure/`, mark the task `[~]` in this plan. A task becomes `[x]` only with its commit SHA and its evidence class, written as `commit <sha>`.
- The levels 1–4 run stays byte-identical: a run with only `--inventory` writes the same 2 files as today. Task 1.G1 proves it with a test.
- These tasks write no database. The deletion of old articles stays in Phase 7, after Daniel approves the level, with a backup first.

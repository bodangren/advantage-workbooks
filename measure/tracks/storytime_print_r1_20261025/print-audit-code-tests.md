## What this file holds

This file holds the code-test list of the print audit gate. The PM list version 0.2 has **eleven** rows: C1, C2, C3, C4, E2, E3, E6, E7, F6, H1, and I1. The first PM request named nine rows. Version 0.2 added E6 and E7, so this file holds all eleven.

The maker runs these tests on each proof build, before the PM audit. A test reads data. It does not replace the page images that the auditor reads.

Each row below gives the real input paths of this repository, the test that covers the row today, the gap, and the planned test. A planned test has no name in the repository yet. Its name is chosen by the Red role of the task that adds it.

Paths are relative to the repository root `/home/daniebo/Desktop/Workbooks`. `W` means each of `content/storytime/l2/w01.json` to `w08.json`.

## How the maker runs the list on a proof build

- `CODE_TESTS` (one `heavy-run.sh` command): `cd dashboard && CI=true npx vitest run __tests__/storytime-print-a48-part3a.test.ts __tests__/storytime-print-step-system.test.ts __tests__/storytime-print-a48-part2.test.ts __tests__/storytime-print-a48-step2.test.ts __tests__/storytime-print-dictation-case.test.ts __tests__/storytime-print-h1-classes.test.ts __tests__/storytime-week.test.ts __tests__/storytime-package-sound-stages.test.ts --maxWorkers=1`.
- `CODE_TEST_LIVE` (one `heavy-run.sh` command): `cd dashboard && npx tsx scripts/storytime/check-weeks.ts --level 2`.
- `CODE_TEST_QR` (one `heavy-run.sh` command, the page render and the decode both run inside it): `cd dashboard && npx tsx scripts/storytime/check-qr.ts <proof PDF> --level 2 --out <report.txt>`.
- The capture names the test name of each row. The auditor writes this name as the proof of the item.
